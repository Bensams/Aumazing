# Aumazing System Demo Recording Guide

Prepared for a complete system walkthrough, 16 September 2026.

Target: approximately 20 minutes after editing. A continuous recording that includes every assessment round and every game will take longer. The timings below are editing targets, not estimates of how quickly a child completes the activities.

This guide follows the current project source. It has not been rehearsed against your installed build or live accounts. Check the starting screens once before recording, especially Premium access, available games, and existing assessment history.

## The Story to Follow

Introduce Aumazing, set up a child, assess the child's activity performance, use the recommendations, play, review progress, demonstrate parent controls, then show the administrator's view of the same system.

Use one fictional demonstration child throughout the main story, for example **Demo Alex**. Keep that child's name, assessment dates, and history consistent across clips. A second fictional child can demonstrate profile switching.

## Before Recording

- [ ] Prepare a dedicated demonstration account with fictional profile details. Keep passwords, verification codes, and personal notifications outside the recording.
- [ ] Choose the installed app for the main demonstration if you need native vibration or on-device analysis. The browser demo can demonstrate the interface, but its analysis route and Premium access differ.
- [ ] Capture the fresh-account and profile-setup segment before completing assessments. Returning users may enter Child Mode automatically.
- [ ] Rehearse exiting Child Mode through the parent gate. The gate may use **Word Code** or **My Own PIN**, depending on the account's settings.
- [ ] Complete the pre-assessment and the current My Path using the demonstration child. Record those stages as you go. Then record the post-assessment and comparison.
- [ ] Keep an already completed demonstration report available as a fallback. Identify it as a previously completed run if you use it.
- [ ] Prepare the administrator account and confirm it can access the portal. A normal parent account does not receive administrator access simply by signing in.
- [ ] If demonstrating Beta Review, use a test child whose research-consent state makes it available there. Verify the report has synced before recording that segment.
- [ ] Check the microphone, app audio, and screen capture. Leave the app voice audible without letting it overpower your narration.
- [ ] Record a short sample that includes the switch between parent and child screens. Parent screens can be portrait on a phone; child screens use landscape. Use a recording layout that shows both without cropping.
- [ ] Check available screen time and the star balance. Leave enough time to finish the planned games, and use a costume preview if the child has insufficient stars.
- [ ] Open the therapy directory and a sample report once so you know what will be available. Rehearse any location or download prompt.
- [ ] For payments, prepare a clearly identified simulation or sandbox. The current browser demo unlocks Premium automatically; it is not evidence of a completed purchase.
- [ ] Keep this guide on another screen or printed beside you. Record one numbered section at a time, leaving two seconds of silence at each end.

## 1. Introduce Aumazing

**Show:** The Aumazing title or app opening screen. Keep the screen still while speaking.

**Say:**

> Good day. We will demonstrate Aumazing, a gamified learning system designed to support young children with autism through guided activities, personalized recommendations, and parent monitoring. We will follow a demonstration child from setup and assessment to practice and progress review, then show the administrator portal. The activity results guide learning inside the app; they do not provide a medical diagnosis.

**Stop here:** The viewer knows what the system does and whose journey they will follow.

**Transition:** "We will begin with how a parent accesses the system."

## 2. Show the Public Website

**Show:** The public Aumazing page, the available download option, and **Try in Browser**, if these are part of the presentation. Open only the access route you rehearsed.

**Say:**

> The public website introduces Aumazing and gives visitors an entry point to the application. For the main demonstration, I will use our prepared app installation.

If using the browser instead, say: "For this demonstration, I will use the browser version."

**Stop here:** The viewer sees the route from discovery to the application. Keep installation time outside this segment.

## 3. Privacy and Account Access

**Show:** The privacy notice and the account screen. Briefly point out registration, sign-in, and guest access. Use a prepared linked demonstration account for the journey that will later appear in the administrator portal.

**Say:**

> A parent reviews the privacy notice before proceeding. The app provides account registration, sign-in, and guest access. I am using a dedicated demonstration account so we can follow its saved records later in the system.

**Actions:**

1. Show the privacy notice without reading every paragraph aloud.
2. Show the account choices.
3. Complete authentication outside the captured view, or cut directly to the successful signed-in state.
4. If the app opens in Child Mode, use the parent-only exit and complete the gate to reach the parent dashboard.

**Stop here:** The correct demonstration account is active.

**Transition:** "The next step is to create a profile for the child."

## 4. Create the Child Profile

**Show:** The three setup stages. Capture this before the demonstration child already has a completed profile.

| Stage | Do | Say |
|---|---|---|
| Child details and appearance | Enter the fictional name and date of birth, then choose an avatar, character, and background. | "The profile keeps this child's settings and activity records together. The parent can also choose the child's appearance and game background." |
| Music, voice & sound | Select the language and voice, briefly preview sound, then continue. | "The parent can adjust the sound and spoken guidance to suit the child's preferences." |
| Almost Done! | Choose a reward preference and screen-time setting, then finish setup. | "The parent also chooses how completed activities are celebrated and sets an initial play limit." |

**Stop here:** The saved child's name appears on the dashboard.

**Transition:** "With the profile ready, the parent can manage the child's learning from this dashboard."

## 5. Orient the Viewer on the Parent Dashboard

**Show:** The selected child, assessment action, **Enter Child Mode**, **History & Progress**, **Therapy Directory**, and Settings.

**Say:**

> This is the parent dashboard. It brings together the selected child's assessment status, activity records, progress, and screen time. The parent can start an assessment, enter Child Mode, review history, or change settings from here.

**Actions:** Point to each main area once. An empty history is expected for a fresh child; say "These sections will fill as activities are completed."

**Stop here:** The viewer understands the dashboard's role. Start the assessment next.

## 6. Run the Pre-Assessment

**Show:** Assessment introduction, parent acknowledgment, optional research consent if prompted, and the sensory-comparison choice.

**Say:**

> The pre-assessment establishes a starting point using four guided games. Before it begins, the parent acknowledges the purpose of the activity and chooses whether to allow the optional sensory comparison. The app records activity measures such as correct responses, errors, response time, and the support used during play.

Research participation is a separate optional choice. Describe the choice selected on screen; do not present research consent as mandatory for using the assessment.

**Play order:**

| Order | Game | Narration while showing a representative interaction |
|---|---|---|
| 1 | Copy Me | "The child watches a sequence and reproduces it." |
| 2 | Do What I Say | "The child follows the instruction and chooses the matching object." |
| 3 | My Turn, Your Turn | "The child waits and responds during their turn." |
| 4 | Match It | "The child identifies matching shapes or objects." |

Let the instruction finish before answering. Show one clear interaction per game, then use an edited segment of the remaining rounds. Complete the actual run before showing its result.

**Editing line:** "The repeated rounds have been shortened in this recording. All four assessment games were completed before this result was produced."

Use that line only if it describes the footage. When using an earlier run instead, say: "I will now open a previously completed demonstration assessment to show the result view."

**End sequence:** Show the completion celebration, the request to return the device to the parent, parent verification, the game summary, and then the full assessment summary.

**Stop here:** **Assessment Summary** is visible.

**Transition:** "Now we can see how the recorded activity is turned into learning guidance."

## 7. Explain the Assessment Summary

**Show these sections in order:**

1. **Overall Performance** and the counts that support it.
2. **Game Results** for the four games.
3. **Developmental Profile**: Communication, Social Interaction, Play Skills, and Attention.
4. **Recommended Settings** and the available apply action.
5. **Recommended Activities** and their starting levels.

**Say:**

> The summary shows how the child performed in these activities and identifies areas that may need more support. The profile uses labels such as Needs Support, Emerging, and Strength. The system then recommends activity settings and a sequence of practice activities with starting levels. These results help the parent decide what to practice inside the app.

Point to one actual result and its related recommendation. Use the values on screen; avoid memorizing a percentage that may change between runs.

**If asked how the analysis works:**

> Supported native builds try the on-device model first, followed by the cloud prediction service and rubric scoring if needed. The parent-facing narrative can also use a summarization service, with a local summary available when that service is unavailable. The displayed result should be described according to the analysis source shown for that run.

The browser does not run the native on-device model. A model-confidence value is confidence in that analysis, not a probability that the child has autism.

**Stop here:** One recommendation has been explained and the viewer can see **Go to My Path**.

**Transition:** "We can open those recommendations directly as playable activities."

## 8. Follow My Path

**Show:** **Go to My Path**, or return to the dashboard and open **Recommended Module**. In Child Mode, the path is available as **My Path**.

**Say:**

> My Path turns the recommended activities into an ordered learning sequence. It uses the recommended starting levels, and the child progresses through the steps as activities are completed.

**Actions:**

1. Pause briefly on the path so viewers can see its order and completion state.
2. Open the first available step.
3. Complete one whole game, including its final interaction.
4. Let the celebration and star sequence finish.
5. Show the resulting path progression or next-step transition.
6. Capture the remaining path steps in additional clips so the completed-path state is available for Section 11.

The exact games and number of path steps depend on the assessment and available content. Read the actual path on screen. Keep assessment rounds, My Path activities, and free practice distinct in your narration.

**Stop here:** The viewer has seen a recommendation lead to a completed activity and recorded progression.

**Transition:** "The child can also explore the wider game library."

## 9. Show the Complete Game Library

**Show:** The Child Mode category view, **All**, and the categories **Communication**, **Social Interaction**, and **Play Skills**. Games may appear under more than one category.

**Say:**

> Aumazing currently includes twelve games. They provide different ways to practice following instructions, matching, imitation, turn-taking, sorting, tracing, routines, and social responses. The four assessment games are also part of this library.

Use the checklist below to avoid missing a game. The first four were already demonstrated in the assessment; the other eight can appear in a short montage. For each additional game, show its title and one meaningful interaction. Complete at least one practice game from start to finish.

| Shown | Game | What the viewer should see |
|---|---|---|
| [ ] | Copy Me | Watch a sequence, then copy it. |
| [ ] | Do What I Say | Follow the prompt and choose the requested object. |
| [ ] | My Turn, Your Turn | Wait for the child's turn, then respond. |
| [ ] | Match It | Select a matching shape or object. |
| [ ] | Sari-Sari Store Sorting | Move a picture into its matching category basket. |
| [ ] | Trace It | Trace a letter or number along the guide. |
| [ ] | Tulong, Kaibigan! | Give the friend the object they request. |
| [ ] | Hintay! | Wait for the signal, then tap. |
| [ ] | Ano'ng Susunod? | Put the steps of a routine in order. |
| [ ] | Sabay Tayo! | Follow the buddy's gaze and select its target. |
| [ ] | Kumusta! | Respond to the buddy's greeting. |
| [ ] | Ano'ng Nararamdaman? | Choose the expression that matches the friend's feeling. |

Administrator availability settings can hide a registered game. Check that all twelve intended games are enabled in your demonstration environment before promising to show all twelve.

**Stop here:** The viewer has seen the range of mechanics and the library's organization.

## 10. Rewards, Stars, and Costumes

**Show:** A genuine game-completion celebration, any earned-star display, the lobby's **My Costumes** entry, and a costume preview.

**Say:**

> Completed practice activities can earn stars, and the child can use them for character costumes. Every costume can be previewed. Parents can control the star system and whether spending stars requires approval.

**Actions:** Preview a costume, then equip an owned one or purchase an affordable one with earned stars. Show the character wearing it. If there are insufficient stars, complete the preview and return without pretending a purchase happened.

Stars reward participation under the configured rules; they are not a medical progress score. The costume shop uses earned stars, while Premium is a separate account-access feature.

**Stop here:** The viewer sees the connection between play, rewards, and the child's character.

**Transition:** "After the recommended path is complete, the parent can review another assessment."

## 11. Post-Assessment and Comparison

**Required starting state:** The current My Path is complete and this cycle does not already have a post-assessment. The dashboard can then display **Start Post-Assessment**.

**Show:** Completed My Path, the post-assessment entry, representative footage of the post-assessment, parent handoff, and its result.

**Say:**

> Once the recommended path is complete, the parent can start the post-assessment. This provides another recorded assessment that can be compared with the earlier result when the runs are comparable.

For an existing history record, use: "I am opening the demonstration child's completed post-assessment so we can review the comparison."

**On the comparison screen, say:**

> Here the parent can inspect the earlier and later results and see which measured areas changed or remained steady. This is a comparison of performance inside the activities. It does not establish clinical improvement or prove that a change was caused by the app.

Show the actual dates and at least one before/after value. If no comparable pair exists, present the saved individual results and state that this record does not yet have a comparison. Avoid promising an increase.

**Stop here:** The viewer understands the full assessment, practice, and reassessment cycle.

## 12. History, Reports, and Export

**Route:** Parent dashboard > **History & Progress**.

**Show:** Assessment history, a completed assessment summary, **Completed My Path & Modules**, **Practice History**, and the **Share as PDF** action. Also open one recent activity's gameplay report from the dashboard if available.

**Say:**

> Parents can return to earlier assessments and review completed paths and practice sessions. This keeps the record available beyond the end of a game. The report can also be exported as a PDF for review or discussion with a professional.

**Actions:** Generate a sample PDF and preview the result. Close the share dialog after showing the available output; sending it to another person is unnecessary for the demonstration.

The separate route **Settings > Export Gameplay Data** offers de-identified CSV, JSON, and a PDF summary. Show that menu briefly if the panel expects data-export coverage.

**Stop here:** One saved record has been reopened and one export action has been shown.

**Transition:** "The parent can also adjust how the child experiences the activities."

## 13. Parent Controls and Multiple Children

**Route:** Parent dashboard > **Settings**.

| Setting | Action | One-line explanation |
|---|---|---|
| Video | Show graphics quality, animation intensity, and instruction text. | "The visual presentation can be adjusted for the child and device." |
| Audio | Change one volume control and preview a voice or music choice. | "Music, sound effects, vibration, and prompt speed can be adjusted." |
| Child Preferences | Show language, reward preferences, appearance, and difficulty. | "The parent can personalize the activity experience and review the difficulty choice." |
| Screen Time | Show daily and per-session limits. | "Play time can be limited, with a break offered at a game boundary." |
| Stars & Costumes | Show earning rules and purchase approval. | "The parent manages the child's star and costume options." |
| Parent Lock | Show Word Code and My Own PIN. | "A parent gate protects access from Child Mode to parent functions." |
| Manage Children | Switch to the second fictional child, then switch back. | "Each child has a separate profile and associated activity history." |

Change only one or two preferences on camera, then demonstrate the visible or audible effect. A full tour of every option can go in an appendix.

**Account-management coverage:** Guest users can see **Bind Account**. Explain linking as an account-management option. Show the account-deletion entry or explain its purpose without deleting the demonstration account. Password recovery can be shown as a separate short insert without capturing email or verification codes.

**Stop here:** Return to Demo Alex and confirm the correct name before proceeding.

## 14. Therapy Directory and Premium

### Therapy Directory

**Route:** Parent dashboard > **Therapy Directory**.

**Show:** Center list and map. When the current account permits it, open center details, select **Find near me**, and show how the selected center relates to its map marker. The Directions action can hand off to a mapping application.

**Say:**

> The therapy directory helps parents find listed centers. Available details and location tools depend on the account's access level. The parent chooses whether to allow location access when using the nearby-center feature.

If location is unavailable, keep the directory visible and say: "The directory remains available; distance ranking requires location access."

This screen is a directory and locator. Do not describe it as appointment booking, a therapist consultation, or an automatic referral.

### Premium

**Show:** The actual access state of the build you are using. On a normal gated mobile build, the Premium page shows the current plan and price. Read the amount shown on screen when recording.

**Say:**

> The regular product includes a free first assessment cycle. Premium provides continued personalized learning cycles and additional features such as advanced analytics and fuller therapy-directory access.

The current browser demo and certain distribution builds unlock Premium features for everyone. In that case, say: "Premium features are unlocked in this demonstration edition. I will show the purchase workflow separately using a prepared test flow."

**Payment-demo choices:**

- Local simulation: show the visible simulation label, complete the simulated flow, and say "This is a simulated checkout. No real payment is being made." Its temporary unlock does not create a genuine payment record in the administrator portal.
- Confirmed payment-provider sandbox: use the prepared test flow and identify it as sandbox activity. Show server-confirmed activation only if it actually completes.
- No prepared test environment: show the plan and checkout entry point, then close it. A real purchase is unnecessary for this presentation.

**Stop here:** The viewer understands the directory and the access model that is actually on screen.

## 15. Show Saving and Synchronization

**Show:** The recently completed demonstration session in history and the app's sync state. Before recording the administrator segment, verify that the same demonstration record is available there.

**Say:**

> The app keeps activity records locally and synchronizes supported account data when a connection is available. The parent can revisit saved activity, and authorized system views can use synchronized records.

An optional offline insert can show a prepared activity working without a connection, then the saved session after reconnecting. Rehearse it first. Do not claim all functions work offline: authentication, payments, live directory updates, and administrator access have network dependencies.

If sync has not completed, say "This record is saved locally and is waiting to synchronize." For the portal, use an explicitly identified earlier synced demonstration record.

**Transition:** "We will now switch to the administrator portal and inspect the system's management features."

## 16. Administrator Portal

**Starting state:** The authorized administrator account is already authenticated, using demonstration records. The portal has eight navigation sections.

**Opening line:**

> The administrator portal supports system oversight, account management, game availability, center information, review of consented research records, and payment monitoring. Access is restricted to administrator accounts.

Follow this order even though the navigation rail has a slightly different order:

| Order | Section | Show | Say |
|---|---|---|---|
| 1 | Dashboard | System Overview and a date-range choice. | "The dashboard summarizes recorded activity and the current system state." |
| 2 | Accounts | Search for the demonstration parent and show available account controls. | "Administrators can inspect parent accounts and manage their account status." |
| 3 | Games | List of games and availability controls. | "This section controls which existing games and learning modules are available." |
| 4 | Centers | Center list and an existing center's edit form. | "Administrators maintain the center information used by the parent directory." |
| 5 | Rubric | Scoring configuration and level explanations. | "The rubric provides configurable criteria used in the system's scoring process." |
| 6 | Beta Review | A consented demonstration child's report. | "This view brings together gameplay indicators, rubric outcomes, recommendations, and pre-versus-post comparisons for review." |
| 7 | Audit Log | Existing entries and filters. | "The audit log records supported administrative actions for traceability." |
| 8 | Payments | Payment statuses and Premium entitlements. | "This section shows recorded payments and Premium access information." |

Spend most of this segment on **Beta Review**, because it connects the app journey to the administrator view. Show its sections in order:

1. Gameplay Indicators: Pre-assessment, Recommended module path, Post-assessment, and Practice mode.
2. Rubric Outcome.
3. AI Recommendation.
4. Pre vs Post Comparison.
5. SPED Validator Sign-off.

**Connection line:** "These sections keep the assessment, recommended practice, and later assessment distinguishable in the child's record."

The sign-off form is a review workflow. Show an existing authorized review or the empty form; do not create a professional sign-off merely to fill the demonstration screen.

For management pages, opening a form and explaining its fields is sufficient. A live change should use an isolated demonstration record. Do not suspend the account you are using, hide games needed by another clip, alter shared scoring settings, or edit a real center simply for a visual effect.

The Games page manages availability of existing content; do not claim it builds new games. A local simulated purchase is not expected to appear as a real portal payment.

**Stop here:** All eight portal sections have appeared, and one demonstration report has been explained.

## 17. Closing Script

**Show:** The parent dashboard or Aumazing title. Hold the final screen for two seconds after speaking.

**Say:**

> That completes our Aumazing demonstration. We have shown the journey from parent and child setup to assessment, recommended practice, rewards, and progress review. We also demonstrated parent controls, reports, the therapy directory, and the administrator portal that supports the system. Together, these features provide a structured way to guide learning activities and monitor performance over time. Thank you.

| Situation | Action | Line to use |
|---|---|---|
| You forget a sentence | Pause for two seconds and restart that sentence. | No explanation is necessary; remove the first attempt during editing. |
| You open the wrong screen | Return to the last known checkpoint and restart the short clip. | "Next, we will look at [section]." |
| A game instruction is speaking | Stop your narration until it finishes. | "The child first receives the instruction, then responds." |
| A page takes too long to load | Pause the clip and resume after it loads. | "This is the saved demonstration record." |
| The post-assessment button is missing | Check the selected child, path completion, and whether a post-assessment already exists. | "For the comparison, I will open a previously completed demonstration run." |

| A result differs from rehearsal | Read the actual value. | "This run shows [value/label] for [area]." |

| There are insufficient stars | Preview a costume or equip an owned one. | "The child can preview this costume while working toward the required stars." |
| Location is unavailable | Continue with the center list. | "The directory remains available; distance ranking requires location access." |
